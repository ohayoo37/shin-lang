# Project governance

SHIN is an open-source, maintainer-led project. Source, ordinary design discussion, issue tracking and pull-request review are public. Everyone may propose changes or maintain a fork under the MIT license.

## Responsibilities and decisions

The current maintainer is [@ohayoo37](https://github.com/ohayoo37). Contributors can propose and review changes; maintainers decide what enters the official branch and publish releases. Public participation does not grant direct repository write access.

Routine fixes use a focused pull request. Substantial language, architecture or compatibility changes should start with a Discussion or Issue that explains the problem, alternatives, examples, security impact and migration cost. Maintainers seek input and record acceptance, requests for revision or reasons for declining in the public thread. There is no formal voting process at this stage. Private vulnerability reports and sensitive conduct matters are exceptions to public discussion.

Review considers correctness, compatibility, maintainability, documentation, test evidence and consistency with explicit capabilities and checked data. Maintainers may defer changes they cannot responsibly maintain. CI is evidence, not an automatic merge decision. Response times and release dates are not guaranteed.

## Growing the team

People who make sustained, constructive contributions may express interest in maintaining an area. Existing maintainers decide whether to invite them after discussing the scope and responsibilities. Accepted maintainers will be recorded here, with access limited to the responsibilities agreed. No contributor is expected to volunteer indefinitely.

Changes to this governance document are proposed through pull requests so the community can discuss them. The current project does not claim foundation sponsorship, a governing board or an established multi-maintainer team.
